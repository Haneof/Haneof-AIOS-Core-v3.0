## Integration into the main run chain — the decisive finding

**None of the four subsystems is wired into the normal Runtime/headless path at `259d0353`.**

- A whole-tree search (`git grep -n "NarrativeSegmenter|DimensionCurveTracker|ToolProposalPipeline|ExperienceTracker" 259d0353`) hits only the modules themselves, their package `__init__.py` re-exports, their own test files, and governance documents. `src/aios_core/headless/` and `src/aios_core/runtime/` contain **zero** references.
- `src/aios_core/headless/core.py:30–36` imports only `FusedTurnRuntime` and `SQLiteWorldStore`; `:239` instantiates `FusedTurnRuntime` only. `turn_runtime.py:16–121` imports contain no `narrative` / `curves` / `tools` / `experience_tracker`; the only related import (`:32`) is the pre-existing `CommunicationExperienceService`, which `turn_runtime.py:324–328` instantiates and `:2626–2640` calls — that is the **old** service, not `ExperienceTracker`.
- The four classes take `store: SQLiteWorldStore` in their constructors and never call a model/LLM (the only "model" hit in the four files is a suggestion string in `dimension_curve.py:367`). They are a deterministic mechanical layer.
- One genuine UNKNOWN is preserved: `headless/core.py:48–74` loads a caller-supplied `module:attribute` handler string via `importlib`. Static analysis cannot exclude a deployment configuration pointing at a new class — but the four classes' constructor signatures do not match the `ModelHandler` contract (`RuntimeSnapshot -> ModelDirective`), and no configuration, document, or code in the range designates them as handlers. This is recorded as UNKNOWN, not as integration evidence.
- Nuance: `ExperienceTracker`'s module is indirectly imported when `turn_runtime.py:32` executes `communication/__init__.py:3–8`, but the class is never instantiated and its methods never called. The other three classes are not even module-loaded outside their own tests.
- The four first-class object types (`NARRATIVE_SEGMENT`, `DIMENSION_CURVE_POINT`, `TOOL_PROPOSAL`, `COMMUNICATION_EXPERIENCE`) were already registered before this range (`contracts/enums.py`, `contracts/models.py`, `contracts/registry.py`); `git diff --name-only 24193afd 259d0353 -- src/aios_core/contracts/ src/aios_core/dimensions/ src/aios_core/runtime/ src/aios_core/headless/` is **empty**. That objects can be stored does not mean the services are wired in. No capability is registered for any of the four (`CapabilityRegistry` in `turn_runtime.py:396–1060` contains no narrative/curve/tool-proposal/experience-tracker capability).

- **May be reused as of `259d0353`:** the four modules' code and their 18 unit tests as implemented-and-tested units; the subject-isolation mechanism; the mechanical/deterministic duty boundary; the CI run `39223062778` (success) as evidence that the `p16-convergence-gate` passed at that head.
- **Must not be assumed:** that the four subsystems are live in the Resident run chain; that old RC/Resident evidence automatically certifies the changed Core; that the receipt's "生产级交付" / "100% 满堂绿" language constitutes independent acceptance (no independent acceptance material for the exact new tree was found); that `EXECUTED` proposals execute anything; that curve points without evidence are acceptable.
