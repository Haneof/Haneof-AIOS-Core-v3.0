### B. Hardened fail-closed contract of `regenerate_identity_manifest.py`

PM correctly identified that `--expect-changed` was optional, so `--write` without
it could accept *any* changed harness digest. The tool now enforces:

1. `--write` **requires** an explicit allowlist; without one it exits non-zero.
2. The changed set must **equal** the allowlist — in both directions. An
   unauthorized extra change *and* an allowlisted entry that did not change are each
   refused.
3. Allowlist entries must be well-formed `harness_files:<canonical relative .py>`.
   Naming `source_files` (a protected scope), an unlisted entry, a non-`.py` path,
   an absolute path, a `..` traversal, or a duplicate is refused.
4. Bytecode pollution (`__pycache__` or a loose `*.pyc`) inside the identity-pinned
   tree is refused — the trap that produced `UNAPPROVED_OR_REPLACED_DIRECTORY`.
5. Harness membership is a closed set: an unlisted new file or a missing listed file
   is refused.
6. Any `src/aios_core/**` or `tools/c15_persistence/**` digest drift is refused, and
   such entries can never be allowlisted.
7. Missing or invalid manifest structure (bad JSON, non-object root, absent file,
   missing protected field, empty scope) is refused.
8. Reserialization must be **line-faithful**: same line count, differing lines
   exactly the changed digest lines, each keeping its key and carrying a 64-hex
   transition matching an allowlisted entry. Foreign indentation, compact form and
   reordered keys are all refused.
9. **Every** refusal path returns before the single `write_bytes` call, which is the
   last statement and is reached only after all guards pass.

`Layout` (repo + harness roots) is now parameterized so the guards can be exercised
against throwaway synthetic directories. `@dataclass` was dropped because
`dataclasses` cannot resolve annotations for a module loaded through `importlib`
that is not registered in `sys.modules` — a real crash found by the new tests.

**New tests: `tooling-tests/test_regenerator_fail_closed.py` — 44 tests, exit 0.**
Kept outside `tests/` so the product suite stays exactly 108 methods. Every refusal

## 5. Finding, RED/GREEN receipt, and why the patch was reverted

> **SUPERSEDED — see §0.** The blocker analysis in this section is retained
> verbatim as the evidence that justified escalating to PM. PM subsequently
> authorized Option B; the fix has been applied and the derived identity pins

### Finding

`load_grant` is the single "this TEST_ONLY enrollment is approved" gate. It
validates the domain, version, purpose, `test_only` flag, issuer identity,
Resident identity/UID/key, the embedded public key against the pinned trust copy,
the whole time window, the enrollment-id shape, the instance-id shape, the bounded
exact `operation_ids`, the bounded `request_kinds`, and the revocation record.

It does **not** validate `run_id` or `session_id` — yet two production call sites
treat them as authoritative scope bindings:

* `response_authorization.SignedResponseAuthority.register`:
  `require(identity['run_id'] == grant['run_id'] and identity['session_id'] == grant['session_id'] …)`
* `safe_runner` pre-launch:
  `require(grant['run_id']==run_id and grant['session_id']==session_id and opid in grant['operation_ids'], …)`

Reproduced: an enrollment omitting those fields **passes the approval gate**
(`load_grant` returns it; 18 keys instead of 20) and is only stopped later by a
bare `KeyError: 'run_id'` raised inside the Publisher dispatch loop — after the
Runner's durable request registration has already succeeded. The request can then
never be answered in signed mode, and the failure surfaces as an uncontrolled
`KeyError` two layers below the gate rather than as an enrollment refusal.

**Severity: fail-closed hardening, not an authorization bypass.** No test
demonstrates a response being published that should have been refused; the
security property holds both before and after the patch. What changes is *where*
the refusal happens and in what vocabulary.

### Candidate patch (2 lines, confined to the authorized path)

`CANDIDATE_FIX_enrollment_scope_gate.patch`, in
`harness/r005/response_authorization.py::load_grant`, immediately after the
`request_kinds` scope check and using the file's existing `type(...) is` style:

```python
    require(all(type(grant.get(k)) is str and grant[k] for k in ('run_id','session_id')),
            'enrollment run/session scope required')
```

The real Operator-issued grants recorded in
`reviews/C15_RERUN005_SIGNED_TTYLESS_WINDOW66/reproduction/issue-finalcandidate.py`
