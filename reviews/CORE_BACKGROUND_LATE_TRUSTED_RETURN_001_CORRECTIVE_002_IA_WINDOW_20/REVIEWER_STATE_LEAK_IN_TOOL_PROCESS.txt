2. WHAT THIS ESTABLISHES
--------------------------------------------------------------------------------------------------
(a) The live-return authority state is a module-level ContextVar in the *shared process context*,
    not a value confined to the genuine provider frame. Any code that can reach the module (or
    reach `LiveProviderReturnWindow._issue` through `__globals__` reflection, see
    IA20-OBJGRAPH-002) can ARM this state; the arm survives the caller that armed it and is only
    cleared by consuming it or by an explicit context reset.
(b) Consequently, a stray/residual armed window makes every subsequent genuine provider return in
    that process/call stack raise `LiveReturnAuthorityError` — i.e. the same surface that permits
    forgery (BLK-W20-001) also permits a denial-of-service against genuine late trusted returns.
    The abort above happened in a *reviewer probe* process, but nothing in the mechanism limits the
    effect to reviewers: it is a property of the candidate's authority design.
(c) This observation is NOT itself the blocker and was NOT counted as a probe failure: it is a
    harness artifact of the reviewer's own mint (the reviewer's probe armed the window and did not
    reset it). It is recorded because it independently corroborates the BLK-W20-001 analysis that
    the window is process-global state manufacturable by the caller, and because it explains the
    Suite A v2 -> v3 revision (the v3 harness explicitly resets the armed window before and after
    each probe). See PROBE_REVISION_LOG.md, Suite A row v2.
(d) Consequence for probe design (recorded so the result cannot be spun either way): a probe that
    arms the window and then performs a dispatch must reset it first, otherwise the failure it
    observes is a shared-context residue, NOT fail-closed enforcement. The v2 result above was
    therefore discarded as a probe outcome and the suite re-frozen as v3
    (ec1dc5c2c5406d5d9e74825f62e0a17fb80f8ebd6dc250817fa048511ce292b5), whose 4/4 failures are the
    findings reported in IA_REPORT.md §5.
