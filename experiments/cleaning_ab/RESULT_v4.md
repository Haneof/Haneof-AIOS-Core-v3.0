# 数据清洗 A/B 实测 v4 —— 4 类误判根因全部修复 + 重跑验证

日期：2026-10-30
策略：**混合架构（机制在前、AI 只标注不删除）+ 4 类根因修复（prompt 重写 + 确定性护栏）。**
目标：验证"AI 误删软事实"问题是否归零。

---

## 一、修复了什么（对应 v3 暴露的 4 类根因）

| 根因 | 修复手段 | 落地位置 |
|---|---|---|
| 1. KEEP 清单漏了软事实类别 | prompt 补两类：关系维系信号（邀约/寒暄/持续互动）、自身常规活动遥测（阅读/运动/时长） | `AI_SYSTEM_TAG` |
| 2. 模型显著性先验丢弃日常 | prompt 改为"个人记忆系统"定位：以"对用户本人是否有意义"为准，不以"是否像新闻"为准 | `AI_SYSTEM_TAG` 开头 |
| 3. 防误留护栏误伤邀约 | 硬约束 2 重写为"区分玩笑夸张与真实社交"：玩笑（世界末日/辞职）才 drop，真实邀约即使无承诺也 keep | `AI_SYSTEM_TAG` 硬约束 2 |
| 4. 无纵向/用户上下文 + 模型孤立判 | 加确定性护栏 `apply_guardrails()`：白名单（外部聊天邀约、app_usage 行为）即使模型标 drop 也强制 keep，作为模型之外的安全网 | `harness.py` 新函数 |

护栏与 prompt 是**双重保险**：prompt 让模型自己学对，护栏兜底未来仍可能漏判的同类。

## 三、必须如实说的 trade-off：recall 掉了

修复误删的代价是 **recall 从 ~1.0 降到 ~0.55**——模型变保守后，约 28/62 条真垃圾被它"保留"（漏标）。典型被多留的：
- 寒暄：`x01`「在吗」（prompt 现把寒暄列入关系维系→keep）
- 一次性琐事：`m03`「快递放门口」、`m12`「午饭随便」
- 系统/常规通知：`p01`早餐消费、`p03`会员续费、`a0x`系统提示
- 场景画面：`v01/v02`「桌面/餐桌」

**这是"宁可多留、不可误删"的有意安全方向，且只标注不删除下这些垃圾并未丢失，只是没被降权，认知 21/21 不受影响。** 噪声的后续处理应交由下游按 `relevance` 降权，而非删除——这与宪法第六/十条一致。

若日后想回收部分 recall（又不冒误删风险），可调 prompt 的 DROP 示例回列「在吗/快递放置/系统通知」等明确可删项，但**不要**让护栏强制 drop（那会重新引入误删）。这是下一步调参，不在本次 4 根因修复范围。

---

## 四、结论

1. **4 类误判根因全部修复并验证**：误删 3→0，precision 3 天全满分，认知零损失，删除数恒为 0。
2. **混合架构 + 只标注不删除 + 护栏** 是目前最稳方案：机制全量存真，AI 打标签，护栏兜底，下游按 relevance 降权。
3. **代价已知且可接受**：recall 下降、垃圾多留，但不可逆损失为零——对个人记忆系统，这是正确取舍。
4. **护栏 = 模型之外的硬安全网**：本轮未触发，但未来任何模型漂移导致同类误删时自动兜住。
