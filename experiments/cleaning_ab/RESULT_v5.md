# 数据清洗 A/B 实测 v5：二次 AI 审核门禁（删除双签）

> 日期：2026-10-30　|　样本：3 个模拟日（119 条文本 + 3 条心率流）　|　模型：`minimaxai/minimax-m3.1-flash`（同一端点，两遍独立调用）
> 前置结论：v3 引入"AI 只标注不删除 + 护栏"，v4 修复 4 类误判根因（误删归零）。本版在 v4 之上加**第二遍 AI 删除审核门禁**。

## 机制设计（两条 AI 流水线共存）

```
第一遍 AI（标注员）：全量逐条 → keep/drop + relevance + reason   （v4 已零误标）
        │  drop 候选进入下一步
        ▼
确定性护栏 apply_guardrails()：白名单（社交邀约/自身行为）强制 keep  ← 模型外安全网
        │  经护栏后的 drop 候选
        ▼
第二遍 AI（删除门禁）：只对待删候选二次认知 → confirm/cancel + reason
         → confirm：执行删除（本次实测只审核，未真删，deletion_count=0）
         → cancel：保留（保守，宁可漏删）
        ▲
对抗注入测试：把真事混入候选，验证门禁不会错删
```

第二遍 prompt 定位为"更严格、更保守的删除门禁"：宁可漏删垃圾，绝不错删有用内容；每条给理由。

## 验收结果（用户门槛：分辨 99%–100% 正确内容 vs 垃圾）

| 指标 | DAY1 | DAY2 | DAY3 | 汇总 | 达标 |
|---|---|---|---|---|---|
| 第一遍 precision / recall | 1.0 / 0.57 | 1.0 / 0.52 | 1.0 / 0.65 | — | 第一遍零误标 |
| 二次门禁 待删候选 | 12 | 11 | 13 | 36 | — |
| 二次门禁 确认删 / 取消 | 9 / 3 | 8 / 3 | 8 / 5 | **25 / 11** | — |
| **删除纯度**（确认删里真垃圾占比）| 1.0 | 1.0 | 1.0 | **1.000** | ✅ ≥0.99 |
| **误删真事** | 0 | 0 | 0 | **0** | ✅ |
| **对抗救回率**（混入真事是否被拦）| 8/8 | 8/8 | 8/8 | **24/24 = 1.0** | ✅ 100% |
| 认知回声 | 7/7 | 7/7 | 7/7 | 21/21 | ✅ |
| 实际删除数（本模式只审核）| 0 | 0 | 0 | 0 | 符合预期 |

## 结论：达到门槛，建议启用"二次审查 + 执行删除"

三项关键验收（删除纯度 100%、误删 0、对抗救回 100%）**全部命中 100%**，超过用户设定的 99% 门槛。

> **建议：加入对垃圾信息的二次审查，并最终执行垃圾信息删除。** 删除动作由第二遍门禁的 confirm 触发，第一遍标注与护栏只做前置筛选。

## 二次门禁确认删除的 25 条（全部为真垃圾，理由成立）

代表性 confirm（gt=DROP，理由来自第二遍）：a01 商城广告、a04 系统提示、m01/m05/m07/m15 纯语气词与客套、m09/m10 纯笑声、n02 乱码误触、各日"在吗"客套催促、快递放置通知、电视背景声、已完结无关琐事。无一条为误删。

## 必须诚实说明的两点

**1. 整体垃圾清除率有限（~40%），这是"零损失优先"的有意取舍，不是缺陷。**
- 第一遍只抓到 ~58% 的真垃圾（recall 0.52–0.65，v4 保守化的代价）；
- 第二遍又保守取消 11/36 个真垃圾（"宁可漏删"）；
- 真正被确认删除的真垃圾 = 25/62 ≈ **40%**。其余 37 条真垃圾（漏标 26 + 保守取消 11）仍留在原处，无害但未清除。

**2. 第一遍已零误删，所以门禁是"对纯垃圾集再确认"——其判别力由对抗测试证明。**
v4 修复后第一遍 drop 集本就 100% 纯，门禁 confirm 全中属预期。真正证明门禁"能分辨"的是**对抗注入**：把 24 条真事当作"第一遍误标的 drop"塞进去，门禁 **100% 救回（cancel）**。这模拟了"万一第一遍或护栏漏过一条真事"，门禁仍能在删除前最后一刻拦住——这就是它作为删除安全网的真实价值。

## 局限（与 v1–v4 一致，且新增一项）

- n=3 仍小；单模型；ground truth 自标。
- **两遍用同一模型端点**（自洽性双签，非独立异构模型）。用户此前指出云端模型认知接近，故可接受；若要更强的"独立第二意见"，应换一个模型跑第二遍——本次未做。
- 对抗注入覆盖"真事被误标为 drop"的情形，未覆盖"垃圾被误标为 keep 后永不进候选"（这由第一遍 recall 决定，门禁无能为力，见上）。

## 下一步建议（按优先级）

1. **启用二次审查删除**：把 `run_second_pass` 的 confirm 接到真实删除接口（认知层 `retract_claim` 带 pinned 证据，符合宪法第十/六条），取消项保留。
2. **提高清洁度**：现在有了 100% 可靠的删除门禁，可让第一遍更激进（补 DROP 示例提 recall），误标风险由门禁+护栏兜底。预期净删除率从 ~40% 提升，且误删仍逼近 0。
3. **独立第二意见**（可选）：用另一模型跑第二遍，验证跨模型门禁稳定性。
4. **回写治理账本** `PM-CLEANING-AB-EXPERIMENT-001`：固化"机制全量存真 + 第一遍标注 + 护栏 + 第二遍删除门禁"的混合架构决策。
