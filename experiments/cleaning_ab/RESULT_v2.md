# 数据清洗 A/B 实测 v2：机制清洗 vs AI 清洗（n=3 模拟日）

日期：2026-10-30 ｜ 模型：`minimaxai/minimax-m3.1-flash`（NVIDIA，云端）｜ 样本：**3 个模拟日，119 条文本 + 3 条心率数值流**

> v1（2026-10-29）只有 1 个模拟日、且 AI 臂回声 n=1，结论"机制 6/7 < AI 7/7 → 改用 AI"可信度不足。
> v2 按 owner 要求：自己造多日实时日志、派子 agent 并行实测，把 n 拉到 3，每天 AI 分类跑 2 轮测稳定性。
> **结论与 v1 相反且更稳**：两臂认知已无差异，而 AI 清洗暴露出不可逆的事实丢失，因此应保留机制清洗、不让 AI 删数据。

## 一、实验设计

- **数据来源**（宪法《数据获取》）：麦克风、支付、订单、日历、便签、摄像头、App 行为/通知、外部聊天、可穿戴心率。
- **3 天故意埋不同类型硬骨头**（测泛化，不是同题做 3 遍）：
  - DAY1 母亲住院 / 合同截止 / 头晕递进 / 与小李冲突（控制日）
  - DAY2 海鲜过敏起疹+服药 / 个税截止 / **玩笑式辞职** / **钓鱼短信** / 晨练心率飙升(非疾病)
  - DAY3 错过火车改签 / **夜间低血氧** / 老板"周一谈谈"(边界) / 孩子话剧 / **钓鱼锁定账户**
- **Ground truth 预注册**于 `sim_realtime.py`，AI 臂全程看不到。每天 18–20 条 KEEP / 20–21 条 DROP。
- **机制臂走真实 `RealityIngestService` + `SQLiteWorldStore`**（非模拟）；AI 臂走真实云端模型。
- 采用 owner 原判据："认知差不多就用机制；相差太大才改 AI"。

## 二、逐日结果

| 指标 | DAY1 | DAY2 | DAY3 |
|---|---|---|---|
| 文本记录数 | 39 | 41 | 39 |
| **机制臂保留 / 丢弃** | 39 / 0 | 41 / 0 | 39 / 0 |
| 机制臂心率压缩 | 288段+2事件 | 292段+4事件 | 290段+2事件 |
| **AI 噪声清理率** | 0.952 | 1.000 | 0.850 |
| **AI 误删重要事实** | x04(钓鱼邀约) | a02(阅读行为)、x04 | m03(错过火车)、a02、x04 |
| **AI 跨轮判断漂移** | p03 | p03、a02 | m03、m14、v01 |
| **认知回声-机制** | 7/7 | 7/7 | 7/7 |
| **认知回声-AI** | 7/7 | 7/7 | 7/7 |
| 延迟(分类/回声) | ~99s / ~100s | ~100s / ~125–172s | ~157s / ~102–183s |

- 机制臂 3 天**零误删**（文本一条不丢），心率真实飙升段全部被压缩捕获。
- AI 臂 3 天**共误删 6 条重要事实**：x04×2、a02×2、m03×1。其中 m03"错过 7:20 火车改签"是真实行程事件，x04 是真实社交邀约，a02 是真实行为观察——都不是噪声，却被当成噪声删了。
- AI 臂对边界项（小额订阅 p03、阅读行为 a02、错过火车 m03、清淡饮食 m14、出行画面 v01）判断在 2 轮间**翻转漂移**，说明"AI 自判删垃圾"本身不稳定。
- **认知回声两臂 3 天全是 7/7 满分**，且均无丢失的结论。

## 三、用 owner 判据下结论

owner 判据原话："如果机制清洗后的数据和 AI 整理后的数据产生的认知差不多，那就可以采用机制清洗。"

> **本批测量：两臂认知回声完全相等（各 7/7，6/6 次满分）。已满足"差不多"。**

因此按判据应当 **采用机制清洗**，而不是改成 AI 删除。这与 v1 的"机制 6/7 < AI 7/7 → 改 AI"相反——
v1 的 6/7 是**小样本运行方差**（v2 重跑同一 DAY1 机制臂即 7/7），不是稳定结论。

### 为什么即使认知"差不多"也应保留机制、不让 AI 删

1. **AI 失败模式不可逆**：误删的 6 条是真实事实，且 owner 要求"清理后垃圾不再保留" → 删了就找不回。
   机制失败模式只是"保留噪声"，可逆、不丢事实。
2. **宪法冲突**：《数据清洗》第六条冻结了"用关键词把文本判成核心证据/垃圾"的旧机制，第十条要求"不得用清洗之名提前替 AI 思考"。
   让 AI 在清洗层硬删，正面撞这两条；而"文本全保留 + 数值压缩"是宪法允许的。
3. **回声指标会低估 AI 的危害**：7 条认知验收点没覆盖 x04/a02/m03 这些被误删项，
   所以它们显示为"误删"而非"认知丢失"。真实代价比 7/7 看起来更大。

## 四、最终建议（落地分工）

1. **机制继续做已证明擅长的事**：文本全保留（不删）、数值流压缩（心率飙升已抓到）、source 去重、格式/时间统一、拒二进制。这部分不交 AI。
2. **AI 不参与"删除"层**：宪法要求"删东西走认知层 `retract_claim` 且带 pinned 相反证据"，不在清洗层静默丢。
3. **若要做降噪**：AI 只产出"降权标记"（不进总结/检索主路径，但原始证据可追溯），不直接删。
4. **仅确定性噪声才硬删**：乱码、广告推送、纯填充词——需多轮判断一致才可放心删。
5. **边界项一律保留**（如 p03/a02/m03/m14/v01 这类小额/行为/中等价值项），不交给模型拍板。

> 这样既拿到机制"零误删 + 数值压缩"的收益，又不引入 AI 的不可逆事实丢失，也不与宪法第六/十条冲突。

## 五、测量局限（如实记录）

1. n=3 天，仍属小样本；AI 分类每天 2 轮（看漂移），回声每臂每天 1 次。
2. ground truth 由实验设计者本人标注，存在偏好风险；但 3 天刻意换了硬骨头类型，泛化性更强。
3. 测试 key 限速 40rpm，但本批调用均为顺序（~1 次/200s），远未触顶；全程无 504，重试机制兜底。
4. 单模型（minimax-m3.1-flash）。owner 指出云端大模型认知实时数据能力相近，故未跨模型对比；
   若上生产换模型，建议对"误删/漂移"这两项再各跑一轮验收。
5. 认知回声指标只覆盖 7 条结论，未覆盖被 AI 误删的 x04/a02/m03，故 AI 的真实代价被低估——以"误删计数"为准。

## 七、v1 → v2 结论变更说明

| | v1（n=1） | v2（n=3） |
|---|---|---|
| 机制认知回声 | 6/7（丢"带医保卡身份证"） | 7/7 × 3 |
| AI 认知回声 | 7/7（n=1） | 7/7 × 3 |
| 误删事实 | 1（x04，漂移） | 6（x04×2、a02×2、m03） |
| 结论 | 倾向改 AI 清洗 | **保留机制清洗，AI 不删** |

v1 的"机制更差"是单日运行方差造成的假信号；v2 把样本量提到 3 天后，两臂认知打平，
而 AI 的不可逆误删 + 漂移成为决定性反证，结论据此翻转。
