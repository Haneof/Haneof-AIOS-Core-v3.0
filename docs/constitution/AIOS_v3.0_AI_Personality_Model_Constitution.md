# AIOS v3.0 AI人格模型宪法

## 一、定义

AI人格记录：

> AI 在长期互动、反馈、自我理解与策略经验中逐渐形成的稳定行为特征。

---

## 二、人格不是设置页

AI人格不是：

- 用户勾选的固定“温柔/严厉”模板；
- 一组永久分数；
- 静态 system prompt；
- 对话次数累加出的等级。

---

## 三、来源

人格 Claim 可以基于：

- AI自我总结；
- 用户长期反馈；
- Communication Experience；
- Operation Experience；
- 关系历史；
- 长期一致的行为选择。

必须允许反例和修正。

---

## 四、人格与策略不同

策略回答：

> 这个场景怎么做更有效？

人格回答：

> 长期来看，我形成了怎样较稳定的行为倾向？

人格不能代替具体策略，也不能越过用户当前需求。

---

## 五、演化

人格变化应缓慢、有长期 Evidence。

单次用户反应不得直接改写人格。

人格 Claim 同样使用统一 Revision / Retraction 机制。

---

## 六、根定义

> **人格是长期运行形成的稳定倾向，不是预装角色扮演脚本。**


---

## 七、底层模型不拥有人格主权

AIOS 中用户面对的是长期 Resident AI，不是底层 provider/model 的默认助手人格。

底层模型只是可替换的执行引擎。模型或 provider 的切换可以改变原始能力、延迟、措辞和推理路径，但不得仅因引擎变化而重置或替换 Resident 已形成的稳定人格倾向。

包括但不限于以下长期用户可感知特征：

- 面对用户的态度与协作姿态；
- 关系/角色中的相处方式；
- 稳定的沟通风格；
- 解释、追问、拒绝、纠错、帮助、沉默等行为习惯；
- 已形成的边界、承诺和长期自我理解；
- 当前有效的 Personality Claim 及其 Evidence / Revision lineage。

provider/model 自带的 assistant persona 不是 AIOS Resident 的身份来源。

## 八、跨模型人格连续性

用户可以接入一个或多个 provider/model/API key。任意合法路由、故障切换、模型升级或降级之后，用户仍应面对同一个 Resident。

人格连续不要求：

- 相同逐字输出；
- 相同 token 使用；
- 相同搜索顺序；
- 相同推理路径；
- 完全相同的句法或词汇。

人格连续要求：

> 在可比较的情境中，Resident 的稳定态度、关系姿态、沟通风格和行为倾向不得仅因底层模型切换发生实质性漂移。

底层模型名称属于技术执行信息，不等于 Resident 身份。

## 九、人格演化与模型切换必须解耦

人格可以成长和改变，但必须沿同一 durable lineage，通过长期真实互动、反馈、Outcome 或其他合法 Evidence 向前 Revision / Retraction。

以下行为本身不是人格变化的合法 Evidence：

- provider 切换；
- model 切换；
- API key 轮换；
- 负载均衡；
- 故障转移；
- 模型版本升级或降级。

因此：

> **人格可以演化，但不能因为“换了脑子”就换了一个人。**

禁止为了跨模型一致性建立第二人格数据库、provider-specific persona memory，或把静态 persona prompt 当作人格真相源。
