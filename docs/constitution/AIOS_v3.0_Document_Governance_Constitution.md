# AIOS v3.0 文档治理宪法

## 第一条：模块化原则

AIOS v3.0 宪法采用模块化结构。

一个核心机制对应一个独立文件。

文件之间通过引用连接，不重复定义同一机制。

## 第二条：双仓融合原则

当前 AIOS v3.0 来源于两套历史资产：

- `Haneof/fantonghui@aios-2.0`
- `Haneof/Haneof-AIOS-Core-v3.0@main`

融合期间不得按“新仓一定优于旧仓”或“旧代码已经实现所以必须保留”进行裁决。

应逐机制比较：

- 理念是否符合当前 AIOS 目标；
- 是否保持事实与认知边界；
- 是否允许长期修正与成长；
- 是否避免硬编码替代高阶认知；
- 是否已经有可靠实现资产；
- 是否有利于先形成最小可运行闭环。

当前融合解释入口：

`AIOS_v3.0_Fused_Baseline_Registry.md`

## 第三条：职责隔离原则

每个模块只负责自身范围。

典型边界：

- 数据获取负责信息进入；
- 数据整理负责机械压缩与事实保留；
- 维度负责世界观察轴；
- Summary负责单维时间整理；
- ALL_DIMENSIONS负责跨维观察投影；
- 智能索引负责找到世界；
- 智能推荐负责决定本轮是否自动带入相关历史；
- 上下文中控负责装配模型上下文；
- AI认知负责意义、判断、关系与策略；
- Runtime负责连接能力和运行闭环。

## 第四条：事实与理解隔离

事实记录、总结结果、认知结果必须保持边界。

事实不可因为认知变化而修改。

认知可以随着新证据调整。

## 第五条：新增机制规则

后续新增能力必须：

1. 明确所属机制；
2. 创建独立文档；
3. 建立与现有模块关系；
4. 避免向综合文件无限堆积；
5. 明确输入、输出、边界、失败与修正方式。

## 第六条：历史 FINAL 文件管理

双仓融合完成并重新冻结之前，历史文件名中的：

- FINAL；
- Authority；
- Freeze；
- Release；
- 唯一最高；
- 唯一宪法基线；

均只代表其生成时的历史状态，不自动覆盖融合工作基线。

历史文件继续保留用于追溯，不再作为独立竞争法统。

## 第七条：最终冻结条件

只有在：

- 双仓机制级融合完成；
- 代码迁移矩阵完成；
- 最小运行闭环跑通；
- 多Agent长期虚拟人生入住测试完成；
- 文档、代码与测试一致；

之后，才允许重新签发 AIOS v3.0 FINAL。
