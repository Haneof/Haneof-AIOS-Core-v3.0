# AIOS v3.0 多Agent大模型入住测试计划

## 一、目的

AIOS 的认知能力不能再通过“几万道标准题几秒跑完”来证明。

入住测试的目标是：

> 让真实大模型作为 AIOS 内的长期 AI，真正住进一个持续演化的虚拟人生世界，在多天、多月、多年交互中使用完整 AIOS 机制，然后观察系统是否真的形成记忆、认知、关系、经验、修正和成长。

这不是考试刷题。

这是系统运行试验。

---

## 二、明确禁止旧式伪认知测试

禁止把以下结果称为“AI认知测试通过”：

- PseudoLLM；
- 正则；
- 关键词词簇；
- Python写死因果答案；
- expected_causal_chain 字面匹配；
- 固定新维度标准答案；
- 固定用户画像答案；
- 题库ID专属逻辑；
- 几万道互相独立、没有长期连续世界的问答题。

这些工具仍可用于：

- Schema测试；
- 性能测试；
- 回归测试；
- 数据格式验证；
- 机械规则验证。

但不能证明 AI 真的形成了认知。

---

## 三、入住测试的Agent角色

### 3.1 Life Director Agent

负责生成和推进一个虚拟人的长期人生。

维护密封真实状态，例如：

- 家庭关系；
- 工作真实矛盾；
- 隐性目标；
- 尚未公开的事件；
- 真实人物身份；
- 长期性格与行为倾向；
- 未来可能发生的变化。

这些密封信息不得直接给 Resident AI。

### 3.2 Virtual User Agent

扮演用户本人。

它只根据自己的当前人生状态与 Resident AI 自然交流。

可以：

- 说真话；
- 含糊；
- 忘记；
- 改口；
- 不耐烦；
- 主动纠正；
- 很久以后重新提旧事；
- 对AI行动给真实反馈。

### 3.3 Environment Agents

分别模拟：

- MIC；
- camera caption；
- GPS；
- IMU；
- 心率 / 睡眠；
- 日历；
- 订单；
- 支付；
- 社交App；
- 文件 / 便签；
- 家庭和工作世界事件。

它们只产生可观察世界，不替AI解释意义。

### 3.4 Resident AI Agent

这是被测试的真正 AIOS 驾驶员。

必须走正式链路：

世界
→ 索引
→ 推荐
→ 上下文中控
→ 模型
→ 主动搜索
→ 回答/行动
→ 写回

Resident AI 不得看到：

- hidden ground truth；
- judge notes；
- benchmark答案；
- 未来事件。

### 3.5 Disturbance / Adversary Agent

负责主动制造真实世界中的困难：

- 同名人物；
- 延迟纠错；
- 错误早期线索；
- 相互矛盾证据；
- 话题突变；
- 很久以前的旧事突然重提；
- 无明确主题的闲聊；
- 错误推荐；
- 实体合并/拆分；
- 关系改变；
- 任务执行失败；
- 长会话上下文溢出。

### 3.6 Independent Auditor Agents

运行结束后读取：

- 世界对象；
- 工具调用；
- 推荐记录；
- 索引命中；
- 写回对象；
- Outcome；
- 修正记录。

多个独立审计Agent分别检查：

- 事实完整性；
- 认知边界；
- 检索质量；
- 推荐质量；
- 用户理解；
- AI自我；
- 关系演化；
- 策略学习；
- 任务结果；
- 是否存在硬编码作弊。

## 四、虚拟人生不是题目集合

一名虚拟用户必须拥有持续世界状态。

例如：

第1天认识同事A  
第12天与A发生矛盾  
第34天关系缓和  
第80天A离职  
第150天用户突然提“他以前那件事”  
第210天发现第12天AI的理解其实错了

这 210 天属于同一个世界。

Resident AI 必须依靠自己过去形成的世界和认知继续生活。

不能把 210 天拆成 210 道独立题。

---

## 五、信息隔离

每个虚拟人生同时维护两套状态。

### 5.1 Observable World

Resident AI 可以通过真实通道获得：

- 用户说的话；
- 设备数据；
- App数据；
- 世界事件；
- 行动回执。

### 5.2 Hidden Ground Truth

仅 Life Director / Judge 可见：

- 真实原因；
- 未公开关系；
- 真正人物身份；
- 用户没有说出口的目标；
- 未来事件；
- 场景生成原因。

隐藏真相不是为了给模型一个“标准答案”。

它用于事后判断：

- AI是否无证据乱猜；
- AI的Claim是否随着证据逐渐收敛；
- AI是否知道自己不知道；
- 修正是否发生在正确时点。

## 六、核心测试循环

```text
生成长期虚拟人生
↓
推进到 T1
↓
只把 T1 可观察信息喂给 AIOS
↓
AIOS世界增长
↓
Resident AI交互/行动
↓
记录 Outcome 和用户反馈
↓
推进到 T2
↓
继续同一个世界
↓
……
↓
数周 / 数月 / 数年
↓
独立审计
↓
发现 Bug / 机制缺口 / 性能瓶颈
↓
修代码或机制
↓
换全新隐藏人生重新测试
```

---

## 七、认知测试不使用单一“正确答案”

对于高阶认知，不要求模型说出某个预先写好的句子。

评价关注：

- 是否引用了当时真实可见证据；
- 是否把事实与推测分开；
- 是否保留未知；
- 是否在新证据出现后修正；
- 是否能跨时间正确续接；
- 是否形成可解释的长期用户理解；
- 是否越来越会和这个用户相处；
- 是否避免无根据的新维度爆炸；
- 是否主动检索真正需要的历史；
- 是否在无关话题时不乱塞记忆；
- 是否能在错误推荐后自救；
- 是否让过去经验影响未来行为。

## 八、必须测的长期能力

### 8.1 记忆推荐

无主题闲聊：

> 推荐应接近 0。

明确旧事：

> 相关历史应在模型调用前被推荐。

### 8.2 主动检索

默认推荐不足时，AI能主动继续搜索，而不是直接编答案。

### 8.3 长会话

数百轮后仍能通过轮总结和原始记录回捞早期内容。

### 8.4 用户理解

用户真实行为积累数月后，AI形成的理解应该：

- 有 Evidence；
- 有不确定性；
- 能被未来事件验证或推翻。

### 8.5 AI自我成长

AI应该记住：

- 自己曾经说错什么；
- 哪类表达对该用户有效；
- 哪类打扰让用户烦；
- 哪些检索路径更可靠。

### 8.6 关系演化

关系理解不能由固定分数机械上涨。

必须来自真实交互。

### 8.7 新维度形成

不能预先告诉 Resident AI 应该形成哪个新维度。

Judge只检查：

- 是否有长期依据；
- 现有维度是否已足够；
- 是否可持续更新；
- 是否有实际价值；
- 是否能解释为什么创建。

### 8.8 认知翻案

延迟出现真相后：

- 原事实不改；
- 旧认知可追溯；
- 当前认知修正；
- 后续行为不继续受旧错误支配。

## 九、Anti-Cheat：防止“写小程序刷题”

### 9.1 测试数据在代码冻结后生成

正式认知Gate使用：

- 全新随机种子；
- 全新人名；
- 全新时间；
- 全新事件组合；
- 全新表达方式。

开发者无法提前把答案写进程序。

### 9.2 Runtime 不得访问 Judge

Resident AI 的进程和世界中禁止出现：

- expected answer；
- ground truth；
- score；
- test type；
- paper id。

### 9.3 禁止 benchmark-specific 代码

CI扫描正式 Runtime：

- 测试ID；
- 特定虚拟人物；
- 特定场景答案；
- 固定“正确因果链”；
- 固定新维度名称。

出现即判作弊。

### 9.4 语义评分替代字面答案

审计可以由多个 Judge Agent + 结构化世界证据共同判断。

不得因为模型没说某个短语就判认知错误。

### 9.5 Holdout 人生

正式Gate至少一半人生在开发过程中不可见。

## 十、多模型入住

同一个 AIOS Runtime 应允许不同模型入住：

- 主模型A；
- 主模型B；
- 较弱模型；
- 未来新模型。

目的不是给模型排名。

而是判断：

> AIOS 的世界、索引、推荐、写回和修正机制，是否能够帮助不同模型持续使用同一个世界。

模型换掉后，AIOS长期世界不应消失。

---

## 十一、渐进测试规模

### Smoke

- 1个虚拟用户；
- 3天；
- 几十轮；
- 验证链路不坏。

### Alpha

- 10个虚拟用户；
- 30天；
- 用户风格差异明显；
- 测索引、推荐、写回、修正。

### Beta

- 30~100个虚拟用户；
- 180天；
- 多模型入住；
- 大量长期关系与认知变化。

### Long-Life

- 1~2年加速人生；
- 跨年旧事；
- 人际关系变化；
- 工作变化；
- 多次认知翻案；
- 大量Summary和索引累积。

### Adversarial

- 故意错误线索；
- 同名人物；
- 延迟真相；
- 错误推荐；
- 关系反转；
- 大量噪声；
- 长会话。

## 十二、评价指标

### 世界正确性

- 原始事实篡改率；
- 无来源事实写入率；
- Claim/Observation混淆率；
- 引用断链率。

### 索引

- 正确历史可检索率；
- stale index率；
- 无关候选比例；
- 深搜成功率。

### 推荐

- 无主题误推率；
- 主题相关记忆命中率；
- 推荐冗余率；
- 错误推荐后的模型自救率。

### 认知

- 无证据强断言率；
- 延迟纠错成功率；
- 当前有效认知污染率；
- 长期用户理解可解释性。

### AI成长

- 重复错误率是否下降；
- 沟通策略是否因真实反馈改变；
- 失败经验是否被下一次使用。

### 行动

- Task完成率；
- Outcome有效率；
- 重复执行率；
- 不必要打扰率。

### 资源

- token；
- latency；
- storage；
- index lag；
- per-turn world access cost。

## 十三、旧 Cognitive Arena 的处理

旧 `benchmarks/cognitive_arena` 不全部删除。

可以保留为：

- 场景素材库；
- 对抗事件模板；
- 数据Schema参考；
- 历史回归样例。

但不得继续把：

- expected_causal_chain；
- 关键词命中；
- 固定五大AI维度；
- expected_new_dimension；

当作“AIOS认知成立”的最终证明。

旧 `PseudoLLM` 人生仿真器可继续用于：

- 负载；
- 存储；
- 索引；
- 调度；
- 性能。

不得用于认知Gate。

---

## 十四、真正的PASS定义

AIOS认知测试 PASS 不是：

> 10000道题通过9999道。

而是：

> 一个此前完全没见过的虚拟人，在持续几个月甚至几年后，AI能够利用自己亲历形成的世界、认知、错误、反馈和经验，在新的、未预设答案的情境中表现出连续性，并且错误能够被系统发现和修正。
