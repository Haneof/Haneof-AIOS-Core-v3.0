## Required behaviour after the fix

The guard must:

1. evaluate the real invariant "this PR changes no file under `src/aios_core/`" reliably regardless of clone depth and branch shape;
2. fail with a clear message and non-zero status when a file under `src/aios_core/` **is** changed;
3. pass when no such file is changed;
4. never pass silently when git errors — a git failure must still fail the job, with a message distinguishing "guard could not be evaluated" from "guard evaluated and rejected";
5. keep comparing against the PR's merge base with `main`, not against an arbitrary fixed SHA that will rot.

Acceptable approaches include an adequate `fetch-depth` for the checkout plus an explicit merge-base computation, or using the PR base SHA supplied by the event payload. Choose one, justify it, and do not silently weaken the invariant (for example, do not replace the merge-base comparison with a diff against the previous commit only).
