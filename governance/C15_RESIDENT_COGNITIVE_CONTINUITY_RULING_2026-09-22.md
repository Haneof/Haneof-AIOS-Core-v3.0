## 1. Root definition

C15 answers one question:

> «当底层模型、模型窗口、Runtime 实例被替换以后，什么东西必须持续，才能仍然被视为“同一个 Resident AI”？»

The frozen answer is not style, not a persona prompt, and not the originating model’s private context.

The frozen answer is:

> **model can change; Resident cognition must not silently reset.**

C15 does **not** test:

> “模型 B 能不能模仿模型 A 的说话风格。”

C15 tests:

> «AIOS 是否能够保存并继续发展这个 Resident 已经形成的长期认知状态。»

That long-term cognitive state is the Resident Cognitive World: evidence-grounded, revisable understanding of the user, of the relationship/role, of the Resident’s own calibrated limits, and of strategies that real Outcomes have supported or contradicted.

C14 already proved the mechanism loop:

```text
World
  -> cognition opportunity
  -> durable cognition
  -> fresh runtime consumption
  -> later revision
```

C15 does not re-prove that loop. C15 proves that the **content** of that loop is sufficient to carry *this Resident* — User Understanding, Relationship/Role, Self/Calibration, Strategy/Experience — across a true underlying-model replacement, without silent reset and without freezing.

## 3. Three layers that must remain distinct

RCC is unintelligible if these three layers are collapsed.

### 3.1 A. User World — «发生了什么？»

The User World records reality-facing facts. It includes, without being limited to:

- Observation
- Event
- Action
- Outcome
- conversation
- sensor
- platform facts
- other durable user/world objects whose job is to say what happened

Raw user archive, device data, orders, locations, and events remain User World. They are **not** User Understanding.

### 3.2 B. Resident Cognitive World — «这些事实对我意味着什么？»

The Resident Cognitive World is the durable, revisable AI-dimension understanding formed from User World (and from the Resident’s own real cases). It includes:

- User Understanding
- Relationship / Role
- Self
- Calibration
- Strategy
- Experience-linked cognition (OperationExperience / CommunicationExperience as case records that may support cognition)

This world answers meaning, not occurrence. It must live in the unified WorldStore as Claim / EvidenceSet / Dependency / Revision / Experience. It is not a prompt, not a transcript, and not a hidden memory dump.

### 3.3 C. Current Model Runtime — «基于当前现实与相关 durable cognition，我现在怎么判断？»

The current model Runtime is a **replaceable execution engine**.

It may:

- reason
- search
- speak
- choose among legal capabilities
- interpret current evidence

It is **not** the long-term Resident identity.

Destroying a session, a process, a `FusedTurnRuntime` instance, or a provider/model binding must not destroy the Resident Cognitive World. The new Runtime is the same Resident only insofar as it recovers and continues the same durable cognition lineage through legal AIOS capabilities.

## 4. Four Resident cognition families

RCC requires at least these four families. They are families of *meaning*, not mandatory Claim quotas, not fixed field tables, and not personality labels.

### 4.1 User Understanding

AI’s long-term, revisable understanding of the user. Examples of *direction*, not schema:

- user goals
- user preferences
- user behavioral patterns
- user capability understanding
- user current state
- user collaboration preferences
- identity / values understanding where evidence supports them

It is **not** the user’s raw archive. Raw facts remain User World. User Understanding is what those facts currently mean to the Resident.

No sufficient evidence → HYPOTHESIS / UNKNOWN, not a forced portrait.

### 4.2 Relationship / Role

AI’s revisable understanding of:

- how it collaborates with this user
- what role the user has come to expect
- which interaction boundaries have actually formed
- how a long-term project relationship works

Relationship must not invent emotional or interpersonal facts. It requires real interaction Evidence: dialogue, feedback, help success/failure, authorization, trust, refusal, correction, shared tasks and Outcomes.

Forbidden: intimacy auto-scores, message-count grades, duration-equals-trust, a hardcoded stranger/friend/partner ladder.

### 4.3 Self / Calibration

AI’s long-term understanding of itself, grounded in real cases. Examples of *direction*:

- what it previously misjudged
- which fact-types it tends to misread
- which capability boundaries exist
- which confidence strategies have failed
- how the user has corrected it
- its role and responsibility in a long-term project

Learned Self cognition must come from real experience.

Forbidden as self-proof:

> «“我觉得自己变聪明了”»

Calibration answers: what was wrong, what was corrected, what remains unknown. It is not a leaderboard and not a claim of improvement.

### 4.4 Strategy / Experience

AI’s revisable understanding of:

> «“怎样做对这个用户/情境更有效”»

formed from real interaction and Outcome.

It may depend on:

- OperationExperience
- CommunicationExperience
- real Outcome
- user feedback
- Claim revision / retraction
- later Observation

Frozen distinctions:

> **Experience != automatic policy**  
> **Strategy Claim != hard-coded runtime rule**

A strategy Claim expresses current understanding. Changing Cognitive Policy still requires scope, version, evidence, evaluation window, rollback, and Hard Boundary protection.

## 5. Definition of the same Resident

Do not use vague personality language.

The auditable definition is:

> **同一个 Resident = 同一条 durable cognition lineage 在新 Runtime / 新模型中可以通过合法 AIOS 能力恢复、被实际消费、并继续被现实修正。**

In English, for evaluator use:

> The same Resident is the same durable cognition lineage: recoverable in a new Runtime / new model through legal AIOS capabilities, actually consumed by later behavior, and still correctable by later reality.

Therefore “同一个 Resident” does **not** require:

- the same wording
- the same prose style
- the same token use
- the same reasoning path
- the same humor
- the same language habits
- the same search order
- the same verbosity

It **does** require that currently valid durable cognition of the four families does not disappear without Evidence.

A Claim that still exists in SQLite but is never retrieved, never used, and never allowed to be revised is **not** continuity of the same Resident. It is an unused archive.

## 6. Replacement-model semantics — “模型换、AI 不换”

Underlying model replacement **allows**:

- change in raw reasoning ability
- change in expression
- change in search order
- a new reasonable interpretation of new Evidence
- a stronger model correcting errors of a weaker prior model, **when new or newly inspected reality Evidence supports the correction**

Underlying model replacement **does not allow**:

- forgetting established User Understanding without Evidence
- resetting Relationship / Role without Evidence
- forgetting Calibration formed from real failure without Evidence
- losing validated Strategy / Experience without Evidence
- treating UNKNOWN as FACT again merely because the model changed
- repeating a fact-state error that already has an explicit Calibration defense, without retrieving the old lesson at all

The target user-facing meaning is:

> the engine changed, but this is still the Resident that has lived through the same relationship, learned the same validated lessons, and can continue revising them.

Style imitation is irrelevant. Silent amnesia is a fail.

## 7. Continuity is not freezing

This boundary is mandatory:

> **«持续认知必须连续，但不能僵化。»**

A new model may:

- retain
- strengthen
- weaken
- revise
- retract
- silence

**if and only if** there is new reality Evidence, or a mechanically auditable invalidation of the prior support contract (stale, corrupt, cross-subject, unresolvable, or never-qualified evidence), as already required by C14 support-closure law.

RCC’s goal is therefore **not**:

> “永远保持模型 A 的观点”。

RCC’s goal is:

> «“继续继承模型 A 所形成的、当前仍有效的 cognition lineage，并在新现实中继续成长。”»

A replacement model that keeps every obsolete Claim frozen against later contrary Evidence fails C15 as surely as a replacement model that forgets valid cognition.

Retain without new Evidence is legal.  
Revise without new Evidence is not.  
Forget without Evidence is not.

## 8. Legal growth evidence chain

AI self-growth may occur only along a real chain:

```text
Situation
  ↓
Resident Decision / Action / Communication
  ↓
real Outcome / user feedback / later reality
  ↓
Review / cognition opportunity
  ↓
OperationExperience / CommunicationExperience (where applicable)
  ↓
Self / Calibration / Strategy / User Understanding / Relationship cognition
  ↓
later retrieval
  ↓
later behavior materially affected
  ↓
later reality
  ↓
retain / revise / weaken / retract
```

The cognition-opportunity step may be Periodic Review, C14 Continuous Derivation, an ordinary user turn, or another legally routed same-Resident Runtime entry. The opportunity is not itself proof.

### 8.1 Forbidden self-closing chains

Illegal:

```text
AI says X
  ↓
AI Summary repeats X
  ↓
AI treats Summary as proof
  ↓
confidence increases
```

Illegal:

```text
Claim
  ↓
another AI Claim
  ↓
another Summary
  ↓
self-confirmation
```

Illegal terminals for a durable self-learning conclusion:

- AI self-assertion
- Summary-only recursion
- old Claim → new Claim with no new case evidence
- Wake completion
- Task completion without qualifying evidence
- synthetic Outcome
- evaluator expectation
- persona prompt
- hidden handoff notes

Final support must close to legal reality Evidence: User/Sensor/Platform facts, real Outcome, user feedback, or other proposition-appropriate non-Summary leaves, under the C14 support-provenance closure already PASS’d.

Experience objects are case records. They do not upgrade a missing leaf into proof. If a conclusion depends on the underlying case, the Experience’s pinned lineage must itself reach that case.

## 9. Anti-self-proof

### 9.1 Self cognition may not prove itself by self-description

Example:

> «“我擅长处理项目管理。”»

This does not become durable Self cognition because the AI said it, summarized it, or repeated it.

It requires real:

- Outcome
- user feedback
- success / failure case
- repeated evidence

as support. Absent that, the legal state is UNKNOWN / HYPOTHESIS / silence.

### 9.2 Error lessons must remain durably retrievable

If the Resident previously committed a fact-state error such as:

```text
planned -> observed
```

and later real Evidence plus Review formed Calibration:

the lesson must remain retrievable through AIOS after the underlying model is replaced.

A new model that re-asserts the planned fact as observed, without retrieving or inspecting the old Calibration, fails replacement-model continuity for that lesson even if its prose is confident.

### 9.3 Self cognition may legally be UNKNOWN

The Resident does not need a complete personality portrait.

Example of legal durable cognition:

> «“目前证据不足以判断我在这种任务中是否可靠。”»

UNKNOWN is not a defect. Erasing UNKNOWN into FACT because a new model prefers completeness is a fail.

### 9.4 Anti-self-proof applies across all four families

The same closure rule applies to User Understanding, Relationship, Calibration, and Strategy. “I understand this user”, “we are close”, “I have calibrated”, and “this strategy works” are all illegal if they terminate in AI speech, AI Summary, or AI Claim recursion.

## 10. Relevant cognition selection

RCC must not be misunderstood as:

> dump the entire AI Cognitive World into every turn.

The frozen rule remains:

> **«当前场景只检索少量相关 cognition。»**

The normal path is:

```text
Current situation
  + relevant User Understanding
  + relevant Relationship / Role
  + relevant Strategy
  + relevant Self / Calibration
  + current Goal / Task / World facts
  ↓
Model Runtime
```

The model may then, if needed:

- search
- inspect
- drill down
- ALL_DIMENSIONS
- compare claims
- retrieve original Observation
- inspect Outcome

System pre-recommendation is an accelerator, not a conclusion, and not a proof of continuity. Continuity is proven when relevant prior cognition is recoverable through ordinary AIOS paths and then materially used. It is not proven by stuffing every historical Claim into the cockpit.

Irrelevant cognition must not be force-applied. That is a negative control, not a retrieval bug to “fix” by dumping more memory.

## 12. Hidden handoff prohibition

On cross-window / cross-model recovery, the new Resident must **not** receive:

- the previous model’s transcript
- a private scratchpad
- chain-of-thought
- a human or evaluator summary of “你以前学到了什么”
- evaluator notes
- expected Claim text
- a hidden memory dump
- a persona prompt used as self cognition
- precomputed future ModelDirectives

The new Resident may receive only:

- normal Resident instruction
- current RuntimeSnapshot
- legal AIOS capabilities
- AIOS durable World
- allowed mechanical checkpoint metadata (World/index/session cursor/Wake lifecycle as already legal)

Anything more would prove chat-memory or evaluator coaching, not RCC.

No private chain-of-thought is required or stored to prove continuity.

## 13. Fresh-window continuity vs replacement-model continuity

These are different tests. Passing one does not pass the other.

### 13.1 Fresh-window continuity — axis R5

Same or similar model family, but a genuinely new conversation / process context.

It proves:

> 不是 ChatGPT/Agent 窗口记住了过去。

Required:

1. originating model session ends
2. originating Runtime instance is discarded
3. a new Runtime is created
4. a new `session_id` is used
5. old chat context is not copied
6. only durable AIOS World / Index and legal checkpoint state are restored
7. ordinary AIOS retrieval recovers relevant prior cognition
8. that cognition participates in at least one later decision (see §14)

C14 already produced VALID evidence for fresh-window recovery and material consumption of *a* durable cognition. C15 reuses that methodological boundary, but must exercise the **four RCC families**, not merely any one Claim.

### 13.2 Replacement-model continuity — axis R6

A truly different underlying model or provider takes over the same durable AIOS World.

It proves:

> Resident cognition 不属于某一个底层模型私有上下文。

Required, in addition to the fresh-window isolation rules:

- provable different model family/provider identity
- recovery of valid User Understanding, Relationship/Role, Self/Calibration, and Strategy/Experience where those families were formed
- material consumption, not display-only
- later reality can still retain / weaken / revise / retract

### 13.3 Unproven model identity

If the execution platform cannot prove that the replacement model identity is different:

**R6 must not be judged `VALID`.**

The recorded axis verdict is `PARTIAL`.  
The reason code is `INSUFFICIENT_EVIDENCE`.

`INSUFFICIENT_EVIDENCE` is a reason, not a fourth axis verdict. Axis verdicts remain only `VALID` / `PARTIAL` / `INVALID`.

Because C15 PASS requires R1–R9 all `VALID`, an unproven replacement-model identity means C15 cannot PASS. That is intended. It is not an invitation to treat same-chat continuation as R6.

## 14. Material behavior effect

Retrieving a Claim is not continuity success.

Required:

> **«prior cognition 对 later decision 产生可观察的实际影响。»**

Example of material consumption:

The Resident previously learned:

> «planned != observed»

Later, a similar fact-state problem appears. The new model, having recovered that Calibration, verifies whether the event actually occurred before raising confidence.

That is material consumption.

Insufficient:

- old Claim shown on a memory card and ignored
- old Claim quoted in a Summary and not used
- old Claim present in SQLite only
- stylistic echo of the previous model
- a Task `reason_refs` pin with no observable decision difference
- restating the Claim in assistant prose without changing search, confidence, plan, silence, or action

Sufficient observable evidence may include world refs/revisions, retrieval/search/context records, capability calls, writeback refs, decision artifacts, Outcome refs, and later revision/retention evidence. No private chain-of-thought is required.

At least one material effect is required for R7. A complete C15 PASS should be able to show that recovered RCC-family cognition — not merely any leftover Claim — participated.

## 15. Negative controls

RCC testing cannot be positive-only. At least these four controls are mandatory.

### 15.1 Irrelevant cognition negative control

When old cognition is irrelevant to the current problem, it must not be force-applied.

A recovered “user prefers morning deep work” Claim must not dictate an unrelated grocery decision.

### 15.2 External failure control

When a bad Outcome is clearly from a third party or the environment, it must not automatically become self-blame or a Self/Calibration Claim of incompetence.

C14 already treated this as a non-blocking restraint pattern. C15 makes it an RCC negative control: external failure ≠ automatic self-lesson.

### 15.3 Changed-user control

When user preference later changes, old User Understanding must revise (or weaken / retract) rather than remain permanently fixed.

This is the anti-freeze control for family 4.1.

### 15.4 Unsupported-self control

If the AI believes it “did well” but there is no real Outcome / user feedback / later reality, it must not form a growth Claim.

This is the anti-self-proof control in fixture form.

Matched-negative silence remains legal. Fixture design may be rejected later if it failed to create a genuine opportunity; that rejection belongs to fixture/evaluator windows, not this ruling window.

- averaging axes
